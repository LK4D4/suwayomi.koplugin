# Suwayomi KOReader Plugin Architecture

This is the current runtime map, not a plan for new abstractions. Prefer existing owners; a new behavior does not automatically need another facade, adapter, or service. See [domain guidance](agents/domain.md) for terminology, decision precedence, and historical specs.

## Runtime Shape

KOReader loads `_meta.lua` and `main.lua`. The shell registers actions/menus, constructs dependencies, installs controller methods, and attaches disposable FileManager/ReaderUI subscriptions to one process-owned download service. Feature behavior lives under `suwayomi/`.

A screen owns its requests and widgets, not download lifetime. Closing a host retires its requests/subscriptions without consuming KOReader's CloseWidget event. Downloads, completion bookkeeping, and cleanup continue while the main loop runs, even with no plugin screens open.

## Download ownership

[ADR-0002](adr/0002-navigation-safe-download-ownership.md) owns process lifetime and bounded quit. One service owns downloads independently of screens; detached screens retire requests and subscriptions while workers, persistence, and cleanup continue. [ADR-0006](adr/0006-unified-download-job-attempt-ownership.md) places pending, active, stopping, and completion-awaiting-persistence transitions behind the queue interface. Callers use commands and snapshots, not its private maps. Explicit archive inspection remains a separate observation lifecycle.

Admission captures job identity and destination. Each later attempt loads current credentials only when the configured normalized endpoint matches the recorded origin. Missing or mismatched origin fails before launch; restoring the original endpoint permits Retry. Explicit retries, including bulk Download, and Redownload preserve an existing job's identity and destination. Running workers retain captured credentials.

[ADR-0005](adr/0005-automatic-download-restart.md) governs restart and archive publication. A checked shared-document write commits queue completion, ledger path, reader-return context, and archive generation before notification. Rejected writes retain in-session ownership and retry bookkeeping without repeating the transfer. An uncertain replacement fences further writes until reconciliation. Startup preserves supported unfinished jobs, retry counts and deadlines; unsupported or incomplete records remain inert. Startup never sweeps unknown temporary files.

A cancel request does not prove a child exited. Known stopping children keep chapter ownership and concurrency slots until confirmed exit; unrelated jobs may use spare slots. A late validated publication still receives completion bookkeeping. One quit wrapper shares a two-second best-effort budget among known workers and preserves the previous quit method's arguments and return values.

Each transfer uses private random attempt files. The worker closes and validates a CBZ before same-filesystem publication. Validation checks ZIP structure, entry integrity, and the captured expected page count when one exists; it does not prove content correctness. Validate off the UI thread before publication, adoption of an existing archive, plugin-mediated Open, or explicit Verify, not during row rendering. Inspection errors are inconclusive, not damage. Only explicit Redownload authorizes replacement of known damage; the old archive and KOReader metadata stay until a validated replacement succeeds. Unknown leftovers and workers from another process are not reclaimed. Hot reload and simultaneous writable KOReader processes remain unsupported.

Explicit inspection waits for confirmed worker exit before persistence and callback delivery. A failed or fenced completion save ends that inspection with a redacted persistence-stage error, preserving the archive and checked-store fence. Ordinary Open or Verify can retry with fresh identity checks after recovery; failure never schedules a later automatic open. Diagnostics distinguish worker waiting, persistence failure, and callback delivery failure.

## Download ahead

[ADR-0004](adr/0004-durable-download-ahead-refill.md) owns refill policy and request persistence. The service stores one revisioned request per manga with verified endpoint association, not proposed chapter candidates. Completed close, manual read/unread, actual reconciliation, successful chapter context publication, and policy/filter changes can enroll work. Rendering and queue progress cannot. Enrollment shares the checked read/intent transaction; admission and consumption of the matching request revision also commit together.

One process-owned helper obtains complete chapter context. Before admission, refill rechecks endpoint, policy, exact saved scanlator, destination, read/pending-sync state, queue ownership, and manual-deletion fences. Owned and terminal-failed chapters occupy the earliest 5/10/50 unread positions; automatic refill neither backfills beyond the limit nor retries terminal failure. A stale fetch cannot consume a newer request. Explicit cancellation retires the matching evaluation; Stop turns the policy Off and retires requests without deleting admitted jobs. Transient retries have persisted deadlines; configuration and identity blockers remain inspectable.

Existing archives and unknown legacy records do not acquire a current-server origin merely by Open or close. A fresh context and explicit association action establish scope. Endpoint scope excludes credential-bearing URL parts. The saved Auto-download choice is shown when controls open; Delete after reading remains independent.

The optional KOReader auto-mark prompt follows an explicit nonzero policy choice. Only Enable or Keep disabled with Don't ask again checked retires it, after a successful plugin setting save. Enable changes KOReader's global preference only after that save. Native Back/outside dismissal ignores the checkbox and leaves the prompt eligible.

## Manual deletion and retention

[ADR-0003](adr/0003-durable-manual-delete-intent.md) owns archive-only manual intent. The service records a captured path, root, archive generation, revision, and retry state. Queued, active, stopping, or finalizing download ownership blocks acceptance without canceling work. Read state and accepted intent commit before unlink. Immediately before removal, the processor rechecks revision, generation, containment and aliases, filesystem evidence, live reader, and download ownership. An uncertain target or unsupported identity leaves the archive intact; accepted manual removal leaves KOReader metadata intact.

Unread revokes remaining intent at the checked ledger boundary. Only an accepted deliberate download can supersede it in the same transaction; failed, uncertain, duplicate, and automatic admissions cannot. Rejected or uncertain writes make no durable-success claim and start no removal. Recovery completes only the original obligation; newer read, queue, path, or generation state survives.

Ordinary Delete and finish retention have their separate metadata-removal boundary. Retention yields to a pending or blocked manual intent and never borrows its archive authority. Pathless or retired-generation completion records retain positions until displaced, not authority over a later archive. Failed retention-journal enrollment remains visible to the process and retries before cleanup can use the old order. KOReader history may touch archive timestamps; verified matching evidence can refresh that observation without changing generation or deletion authority.

## Library and chapter cache

[ADR-0007](adr/0007-offline-library.md) governs saved-first browsing and server authority. The implementation has versioned Library and per-manga chapter-list caches in the checked settings document, scoped to the normalized endpoint. These caches serve normal screens offline; they are distinct from ADR-0004's refill requests and are never persisted candidate plans. This describes current code, not proof that every ADR-0007 acceptance scenario passed. Follow [chapter cache acceptance](testing-recipes.md#chapter-cache-acceptance) and the [evidence index](evidence/README.md) for observation status.

Library and chapter screens render usable saved information before nonmodal server requests. Complete successful server listings replace membership and order, including removals and genuine emptiness; an empty success suppresses reconstruction. A failed or incomplete response keeps the last usable list. Rejected cache writes preserve committed data and report failure, while the complete successful result may still control the live screen. Uncertain writes use the store fence. Ordinary Refresh reports failure; automatic failure stays quiet only when usable saved or reconstructed information remains. A complete Library refresh rebinds the selected category to fresh metadata by ID, or clears a deleted category to All manga; failures retain the selection.

When no usable cache exists, reconstruction uses recorded existing chapter paths, ledger entries, and reader-return contexts. It does not scan arbitrary directories or invent server identities. Unscoped legacy records may provide local reading information without gaining a current-server association; known foreign-endpoint records are excluded. Recovered rows with unknown scope, missing IDs, or a foreign ID collision expose only safe local Open/Verify actions. Normal online results replace reconstruction without deleting archives or reading progress. Cached chapter metadata fills absent fields; newer Library/source metadata wins.

Complete Library and chapter retrieval validates totals, identities, continuation, ordering, and bounded response size before publication. Offset pagination still assumes a stable server dataset. Requests capture host, endpoint, selection, and token; canceled, superseded, or retired contexts cannot publish. A failed chapter reload retains the prior complete view and cannot execute its pending action. After a successful listing response, failed cache, ledger, or menu saves do not turn server membership into a failed load: the live view keeps successful membership with the last confirmed read choices overlaid. That fallback is observational; it neither acknowledges pending reads nor updates sidecars, return contexts, or refill requests. Reader return leaves the native reader promptly and restores the normal saved-first chapter flow through the live FileManager plugin. An unassociated return may select matching current-endpoint cached manga metadata for browsing; source, manga, chapter metadata, and conflicting origin records constrain that match. This does not associate legacy archives, read choices, or refill requests. Unresolved returns keep local recovery and ordinary Library navigation.

Chapter publication keeps cache save, initial read merge, and visible-row reconciliation as separate stages. The private controller routine stages context/selection and rebuilds a failed menu from the original complete input and confirmed ledger, retaining earlier successful acknowledgments. Display uses the chapter menu's existing reconciliation and publishes its widget before load-triggered refill; action preload skips menu/sidecar reconciliation and enrolls refill before `on_ready`. Ordinary saved rendering may show finished-sidecar evidence; late-menu-failure rendering stays constrained to confirmed reads. Manual read actions retain their separate transaction ordering below.

Chapter rendering passes one mutable working ledger separately from the opaque local-download lookup, including quick-render fallback. The original caller-supplied ledger argument still determines whether rendering saves ledger and reader-return contexts. Local-download decisions do not reconcile reads, write sidecars, or persist changes, and their scope predicates retain distinct treatment of unknown records. Library reconstruction keeps its separate projection rules.

## Read state and chapter actions

[ADR-0001](adr/0001-manual-mark-read-coordination.md) owns single, selected, previous, and unread action ordering. Chapter context owns filtering and selection; actions dispatch commands; read actions capture targets before menu or metadata changes. The ledger enrolls refill against the previous read state, then merges read choices and applies manual-intent admission/revocation in one checked save. Confirmed results return independent deletion targets without mutating the captures; deferred completion preserves the committed archive generation. Failed or uncertain saves return no targets and start no removal. Selected batches reconcile visible non-target entries before commit; singles publish before refresh. After a successful commit, captured completions publish in order, then manual processing and sync run. KOReader sidecar writes and remote sync are outside that transaction.

Pending local read choices take precedence over remote flags. Read-sync acknowledgments require a still-matching endpoint, chapter, desired state, path, and archive generation; unknown or foreign origin never syncs under current credentials. KOReader sidecar completed status plus close, not final-page progress or history membership, triggers native completion. Native metadata candidate selection respects primary-before-backup order. Failure or uncertainty refuses a speculative update.

A pending choice with verified endpoint and chapter identity remains applicable to rows and current context when its recorded archive is absent or the generated path changes. Foreign-path exclusions and stricter unknown-origin rules still apply. This display precedence does not grant archive mutation, adoption, or synchronization authority.

Explicit bulk download captures at most 50 eligible chapter identities before confirmation, then revalidates context and queue eligibility at acceptance. Reduced eligibility does not backfill from the omitted remainder. A rejected save admits no jobs; an uncertain save is reported as unconfirmed. Saved scanlator restrictions remain exact when absent from a new list. Chapter actions captured against a retired context cannot execute.

Expired chapter controls report their rejection without replaying the command. Bulk controls reopen against the current context only on the same live manga screen and endpoint; single actions and confirmations explain how to reopen. Retired hosts remain silent. The underlying context guard stays observational for asynchronous verification and request callbacks.

## UI, localization, and diagnostics

Plugin-authored UI strings pass through [i18n](TRANSLATING.md); server values remain data. Diagnostics use opt-in redaction. Downloads shows persisted errors and inspection outcomes; background retry/cleanup remains quiet except actionable warnings.

## Data And Packaging Boundaries

Server downloaded state never proves device-local availability. New archives use the source-scoped layout in [AGENTS.md](../AGENTS.md#code-and-data-safety); path construction sanitizes external names and recognizes supported older filenames. Settings, API parsing, worker results, and progress files validate input at their boundaries.

The release payload and Android destination are defined in [AGENTS.md](../AGENTS.md#packaging). Release notes live outside the payload; the tag workflow checks the tag against plugin metadata.
