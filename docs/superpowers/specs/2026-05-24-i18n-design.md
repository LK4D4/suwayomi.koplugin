# Suwayomi Plugin I18n Design

## Goal

Add internationalization to the KOReader Suwayomi plugin without making the
runtime depend on build tools, network services, or Suwayomi WebUI internals.

The plugin should use gettext-style catalogs, follow KOReader UI language
selection, and make visible plugin text translatable over time. The first
implementation should establish the translation infrastructure and convert a
small UI slice. Later work can convert the rest of the plugin in reviewable
steps.

## Non-Goals

- Do not add a plugin-specific language selector in the first pass. Use the
  KOReader UI language.
- Do not machine-translate all catalogs and ship unreviewed translations.
- Do not translate manga titles, chapter names, source names, server-provided
  strings, URLs, filesystem paths, credentials, or debug data.
- Do not require `xgettext`, `msgmerge`, `msgfmt`, Weblate, Node.js, or Lingui
  on the KOReader device.
- Do not replace or monkey-patch `package.loaded["gettext"]`.
- Do not copy Suwayomi WebUI Lingui catalogs directly. WebUI strings and plugin
  strings have different context and UI constraints.

## Current State

The runtime already imports KOReader gettext in many files:

```lua
local _ = require("gettext")
```

Most visible strings are wrapped in `_()`, but those calls currently resolve
against KOReader's main `koreader` domain. They do not load a plugin-specific
`suwayomi` domain, so they are English fallback strings in practice.

There are about 475 existing `_()` call sites in `main.lua`, `_meta.lua`, and
`suwayomi/`. Many translated modules also use `for _, value in ...` loops. This
is dangerous because `_` can be shadowed by loop variables; this plugin already
has prior bug evidence for `attempt to call local '_' (a number value)` after UI
helper changes. I18n work must avoid adding that crash class.

The release payload currently contains only:

```text
_meta.lua
main.lua
README.md
suwayomi/
```

Any shipped catalogs require release-payload and Android QA guidance updates.

## External Guidance

KOReader core is the closest runtime reference:

- `frontend/gettext.lua` loads compiled `.mo` files from
  `l10n/<locale>/<domain>.mo`.
- It exposes gettext, pgettext, ngettext, and npgettext.
- `make/gettext.mk` extracts strings with `xgettext` and builds `.mo` files with
  `msgfmt --no-hash`.

Community plugin patterns are mixed:

- SimpleUI uses an isolated plugin i18n module and explicitly avoids global
  gettext monkey-patching because that caused cross-plugin breakage.
- KOAssistant uses plugin-local `.po` files and Weblate.
- Zlibrary uses KOReader gettext internals with a wrapper and state restore.

For this plugin, the safest shape is: plugin-local loader, gettext file formats,
compiled `.mo` at runtime, and no global gettext replacement.

## Supported Locales

The target locale set should start with Suwayomi WebUI's current Lingui
locales. As of the referenced `lingui.config.ts`, WebUI lists:

```text
ar de en es fa fr hu id it ja ko pl pt ru vi zh-Hans zh-Hant
```

English is the source locale and does not need a runtime catalog. Every other
locale should be supported as an incomplete catalog from day one. Empty or
partial `msgstr` values fall back to the English `msgid`.

Use this initial mapping:

| WebUI locale | Plugin catalog | Notes |
| --- | --- | --- |
| ar | ar | RTL; verify KOReader bidi behavior with untranslated English fallback. |
| de | de | German. |
| en | none | Source strings are English msgids. |
| es | es | Spanish. |
| fa | fa | RTL; verify KOReader bidi behavior. |
| fr | fr | French. |
| hu | hu | Hungarian. |
| id | id | Indonesian. |
| it | it | Italian. |
| ja | ja | Japanese. |
| ko | ko | Korean. |
| pl | pl | Polish; plural forms matter. |
| pt | pt | Portuguese target matching WebUI. Runtime should also try `pt` when KOReader reports `pt_BR`. |
| ru | ru | Russian; plural forms matter. |
| vi | vi | Vietnamese. |
| zh-Hans | zh_CN | KOReader commonly uses `zh_CN` for Simplified Chinese. |
| zh-Hant | zh_TW | KOReader commonly uses `zh_TW` for Traditional Chinese. |

The runtime loader should normalize aliases before loading:

```text
zh-Hans, zh_Hans, zh_CN -> zh_CN
zh-Hant, zh_Hant, zh_TW -> zh_TW
pt_BR -> pt, then pt_BR if a more specific catalog is later added
<lang>_<REGION> -> <lang> fallback for all other locales
```

The tracked locale registry should keep the WebUI target set visible so future
WebUI locale additions are easy to compare.

## Runtime Architecture

Add a focused runtime module:

```text
suwayomi/i18n.lua
```

Public API:

```lua
local I18n = require("suwayomi/i18n")
local _ = I18n.translate
local N_ = I18n.ngettext
local C_ = I18n.pgettext
local NC_ = I18n.npgettext
```

Responsibilities:

- Detect KOReader UI language from `G_reader_settings:readSetting("language")`
  when available.
- Fall back to native KOReader gettext current language or environment language
  only for local tests.
- Normalize aliases and region fallback.
- Load `l10n/<locale>/suwayomi.mo` lazily.
- Cache loaded catalogs per effective language.
- Return English msgid when no catalog or no translated string exists.
- Preserve KOReader native gettext state after every plugin catalog load.
- Expose `reset()` for tests and future language-change handling.

Implementation approach:

1. Require native KOReader `gettext`.
2. Temporarily save native fields needed by `changeLang`, including `dirname`,
   `textdomain`, `translation`, `context`, `current_lang`, `wrapUntranslated`,
   and plural function state.
3. Point native gettext at the plugin domain and call `changeLang(locale)`.
4. Copy loaded translation tables into plugin-owned cache.
5. Restore every saved native field before returning.
6. Serve all future plugin translation calls from plugin-owned cache.

This reuses KOReader's `.mo` parser and plural handling while avoiding persistent
global state changes. Specs must prove native gettext is restored on success and
failure.

## File Layout

Development files:

```text
l10n/templates/suwayomi.pot
l10n/<locale>/suwayomi.po
scripts/update-l10n.sh
scripts/compile-l10n.sh
scripts/check-l10n.sh
```

Runtime payload:

```text
l10n/<locale>/suwayomi.mo
```

Do not ship `.po` or `.pot` files in release zips. They are source and
translator files, not KOReader runtime requirements.

## Build And Tooling

`scripts/update-l10n.sh` should:

- require host tools `xgettext`, `msgmerge`, `msgattrib`, and `msgfmt`;
- extract from `_meta.lua`, `main.lua`, and `suwayomi/**/*.lua`;
- use Lua mode and UTF-8 input;
- include keywords for `_`, `N_`, `C_`, and `NC_`;
- include translator comments with a stable tag such as `Translators:`;
- update `l10n/templates/suwayomi.pot`;
- merge new strings into every tracked `l10n/<locale>/suwayomi.po`;
- keep obsolete entries out of normal commits;
- fail if placeholder checks fail.

`scripts/compile-l10n.sh` should:

- compile every non-English `.po` to `.mo`;
- use `msgfmt --check --no-hash`;
- write `l10n/<locale>/suwayomi.mo`;
- skip catalogs that have no translated strings only if this behavior is
  documented and tested.

`scripts/check-l10n.sh` should:

- run extraction in a temporary directory or check mode;
- verify `suwayomi.pot` is current;
- verify all `.po` files pass `msgfmt --check`;
- verify compiled `.mo` outputs are current when `.po` changes.

CI should install GNU gettext tools before running l10n checks. KOReader devices
do not need these tools.

## Release Payload

Update `.github/scripts/stage-release-payload.sh` to include compiled catalogs:

```text
README.md
_meta.lua
main.lua
suwayomi/
l10n/
```

Payload validation should allow only `.mo` files under `l10n/`:

```text
l10n/<locale>/suwayomi.mo
```

It must reject:

- `.po`
- `.pot`
- Weblate metadata
- scripts
- generated temporary files
- developer-only docs or specs

README and architecture docs must mention `l10n/` as runtime payload once the
implementation ships it.

## Source Conversion Rules

Every runtime module that uses translated strings should import from
`suwayomi/i18n.lua` instead of `gettext`:

```lua
local I18n = require("suwayomi/i18n")
local _ = I18n.translate
```

Avoid `_` as a loop or callback parameter in any module that uses `_()`:

```lua
for _index, action in ipairs(actions) do
    ...
end
```

Use `N_` for counts:

```lua
local text = T(N_("1 chapter", "%1 chapters", count), count)
```

Use `C_` for short ambiguous strings:

```lua
C_("menu action", "Sync")
C_("status label", "Sync")
```

Use `NC_` only when both context and plural forms are needed.

Use KOReader `T()` templates for placeholders:

```lua
T(_("Could not connect to Suwayomi: %1"), error_message)
```

Do not concatenate translated sentence fragments. Prefer full strings:

```lua
T(_("Downloaded chapters are in %1."), folder)
```

Translator comments should explain placeholders and domain terms:

```lua
-- Translators: %1 is a filesystem folder chosen by the user.
T(_("Downloaded chapters are in %1."), folder)
```

## Translation Scope

Translate:

- menu titles
- dialog titles
- button labels
- settings labels and summaries
- plugin-authored status text
- plugin-authored error explanations
- confirmation prompts
- release metadata description

Do not translate:

- Suwayomi source names
- manga titles
- chapter names
- scanlator names
- extension package names
- server error strings unless quoted inside plugin-authored context
- user paths
- URLs
- credentials
- debug log keys
- persisted settings keys
- GraphQL operation names

For mixed strings, translate the plugin-authored frame and keep external data as
placeholder values.

## Weblate Plan

Do not set up Weblate before the repository has stable extraction and CI checks.

When ready, use a gettext component with:

```text
source language: en
translation file mask: l10n/*/suwayomi.po
template: l10n/templates/suwayomi.pot
```

Weblate should commit `.po` updates only. The repository CI or release workflow
should compile `.mo` files. If Weblate requires generated files in PRs, keep
that decision explicit in the project docs.

Add a translator guide before inviting translations:

- explain locale list;
- explain placeholders;
- explain Suwayomi-specific terms;
- explain incomplete translations falling back to English;
- tell translators not to edit `msgid`;
- ask for device screenshots only with private data redacted.

## Testing Strategy

Add focused specs for `suwayomi/i18n.lua`:

- source locale returns msgid;
- missing catalog returns msgid;
- missing msgstr returns msgid;
- loaded catalog returns translated string;
- base language fallback works, such as `de_DE -> de`;
- alias fallback works, such as `zh-Hans -> zh_CN`;
- plural lookup uses catalog plural rules;
- context lookup returns context-specific translation;
- native KOReader gettext state is restored after successful load;
- native KOReader gettext state is restored after failed load;
- `reset()` clears plugin cache only.

Add conversion specs where needed:

- converted menu labels still match English fallback in current tests;
- converted count strings use `N_`;
- converted short labels use `C_` where ambiguous;
- converted modules do not shadow `_` in loops or callbacks.

Add release checks:

- release payload includes `l10n/` only when `.mo` files exist;
- release payload rejects `.po` and `.pot`;
- Android QA push copies `l10n/` with runtime files;
- staged payload still excludes specs, docs, CI files, and worktrees.

## Implementation Phases

### Phase 1: Infrastructure

Add:

- `suwayomi/i18n.lua`
- `spec/suwayomi_i18n_spec.lua`
- `l10n/templates/suwayomi.pot`
- l10n scripts
- CI gettext install and l10n checks

Convert only `_meta.lua`, `main.lua`, and `suwayomi/plugin/home.lua` to prove
the path without touching large UI surfaces.

Success criteria:

- local specs pass;
- luacheck passes;
- l10n check passes when gettext tools are installed;
- release payload smoke passes;
- English UI remains unchanged.

### Phase 2: Settings And Setup Wizard

Convert:

- `suwayomi/plugin/settings_controller.lua`
- `suwayomi/ui.lua` settings-related helpers
- onboarding connection dialog strings

This is high-value because first-run setup and settings are the most likely
screens for non-English users.

Success criteria:

- settings specs still assert English fallback;
- no `_` shadowing remains in converted files;
- first-run flow shows translated labels with a test catalog.

### Phase 3: Browse And Extension Management

Convert:

- `suwayomi/browse/controller.lua`
- `suwayomi/browse/source_catalog.lua`
- `suwayomi/browse/extensions.lua`
- `suwayomi/ui/browse.lua`

Use context for source-related short labels and keep source/extension names as
external data.

### Phase 4: Library, Manga, Chapters, Downloads

Convert:

- `suwayomi/client/*.lua` user-facing text
- `suwayomi/manga/*.lua`
- `suwayomi/chapters/*.lua`
- `suwayomi/downloads/*.lua`
- `suwayomi/ui/downloads.lua`
- `suwayomi/ui/manga_info.lua`
- `suwayomi/ui/list_rows.lua`

This phase should be split into several PRs because it touches most user-facing
surface area.

### Phase 5: Weblate And Translator Docs

After Phases 1 and 2 are stable:

- add translator guide;
- add Weblate badge only after project exists;
- enable Weblate for the target locale set;
- document translation contribution flow in README or CONTRIBUTING.

## Acceptance Criteria

The i18n rollout is complete when:

- all plugin-authored visible runtime strings are routed through
  `suwayomi/i18n.lua`;
- every WebUI target locale has a tracked `.po` file or documented Weblate
  target;
- release assets include compiled `.mo` files and no source catalogs;
- KOReader devices need no gettext CLI tools;
- missing catalogs and missing strings fall back to English;
- plural forms and context translations are supported;
- CI verifies extraction, `.po` validity, compiled `.mo` freshness, Lua specs,
  luacheck, and release payload contents;
- Android QA instructions include `l10n/` in the runtime push payload;
- docs explain how maintainers update catalogs and how translators contribute.

## Risks And Mitigations

| Risk | Mitigation |
| --- | --- |
| Global gettext state leak breaks KOReader or another plugin | Never monkey-patch `package.loaded`; save and restore native gettext state in specs. |
| `_` loop variable shadows translate function | Rename loop placeholders in converted modules; add focused review checks. |
| Runtime payload accidentally ships `.po` files | Enforce payload allowlist under `l10n/`. |
| Translated text overflows e-ink UI | Convert incrementally and cover compact menus in specs/device QA. |
| Plural forms are wrong in Slavic or Arabic languages | Use `N_` and `msgfmt --check`; avoid hand-written count grammar. |
| WebUI locale names do not match KOReader locale names | Keep explicit alias map and tests for `zh_CN`, `zh_TW`, and `pt_BR`. |
| Weblate churn overwhelms feature work | Wait until extraction, CI, and first UI slice are stable before enabling Weblate. |
